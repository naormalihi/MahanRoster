# MahanRoster – מערכת תורנויות

מערכת לשיבוץ תורנויות ביחידה, לפי האפיון ב-Claude Docs. גרסה 1.0 היא כלי עבודה של נע"ת התורנויות, עם לוח מפורסם לצפייה.

## מבנה המאגר

| תיקייה | מה יש בה | מצב |
| --- | --- | --- |
| `solver/` | מנוע השיבוץ (Python + OR-Tools CP-SAT) | אב-טיפוס |
| `supabase/` | סכמת Supabase, RLS, הגשר למנוע ובדיקות | גרסה ראשונה |
| `web/` | ממשק React למסכי הנע"ת וללוח המפורסם | בהמשך |

## מנוע השיבוץ

המנוע מקבל קובץ JSON אחד לכל ריצה (`Problem`) ומחזיר קובץ JSON (`Solution`). אין בו מספרים אישיים ואין מידע רפואי: חיילים מזוהים במזהה אטום בלבד, וכל הנתונים (דרגה מחושבת, אוכלוסיות, ניקוד בסיס, פטורים מאושרים, היעדרויות) מגיעים כבר מחושבים משכבת הנתונים. החוזה המלא מתועד ב-`solver/mahanroster_solver/models.py`.

```bash
cd solver
pip install -e ".[dev]"

python -m mahanroster_solver generate --months 1 -o problem.json      # יחידה פיקטיבית
python -m mahanroster_solver solve problem.json -o solution.json
python -m mahanroster_solver report problem.json solution.json -o report.md
python -m mahanroster_solver verify problem.json solution.json          # 1 = הפרת כלל קשיח
pytest
```

### מה המנוע מכסה

- **ניקוד:** יחידות יממה, מכפילי סופ"ש, חג ולילה, ונרמול לפי מקדם ההקלה ביום הביצוע.
- **זכאות (אילוצים קשיחים):** אוכלוסייה, דרגה ומגדר; ממלכ"ת יום רק למשרתי הורה ובעלי פטור מזכה; שח"ר; תוקף מטווח; גיוס, שחרור וחודש חסד; פטורים מלאים וחלקיים; היעדרויות; חסימות תאריך; אילוצים אישיים; משבצות קנס.
- **שיבוץ:** מבצעים ועתודות, מנוחה בין תורנויות (גם לעתודה), עתודת חובה מגף המבצע, שיבוצים קבועים, ותקרה חודשית.
- **הוגנות (אילוצים רכים, בתוך כל אוכלוסייה):** הניקוד הצפוי המקסימלי, הפיזור סביב הממוצע, סופ"שים, עתודות, סופ"שים רצופים, ריכוז בשבוע אחד, ועתודת קבע מגף אחר.
- **מחזור ארוך:** חצי שנה נפתרת חודש אחרי חודש. הניקוד, הסופ"שים והעתודות של כל חודש עוברים לחודש הבא, ותורנויות בסוף חודש נחשבות בבדיקת המנוחה של תחילת החודש הבא.
- **נקודת התחלה:** שיבוץ חמדני כרונולוגי (מי שהניקוד שלו הכי נמוך) נותן ל-CP-SAT פתרון מלא וחוקי מהשנייה הראשונה, והפותר משפר אותו.
- **פלט:** הסבר לכל שיבוץ, משבצות שלא אוישו עם הסיבות, סטטיסטיקת הוגנות, ובודק עצמאי של הכללים הקשיחים.

## גיבוי ושחזור

ה-workflow `backup` שומר עותק מוצפן של המסד (הסכמות `public` ו-`auth`, כך שגם החשבונות נשמרים). הוא רץ בכל לילה ולפני כל מיגרציה, ו-`db-migrate` לא מחיל מיגרציה בלי גיבוי שהצליח. כל עותק נשמר 30 יום כ-artifact של הריצה, בלשונית Actions.

**הגדרה חד-פעמית:** מוסיפים סוד בשם `BACKUP_PASSPHRASE` (לפחות 20 תווים) תחת Settings › Secrets and variables › Actions. כדאי לשמור את הסיסמה גם מחוץ ל-GitHub, למשל במנהל הסיסמאות, כי בלעדיה אי אפשר לפתוח את הגיבוי.

**שחזור** (למסד ריק, למשל פרויקט Supabase חדש):

```bash
gpg -d mahanroster-YYYYMMDD-HHMM.dump.gpg > db.dump            # מבקש את הסיסמה
pg_restore --no-owner --no-privileges --clean --if-exists -d "$DATABASE_URL" db.dump
```

לשחזור טבלה אחת: `pg_restore -l db.dump` מציג את התוכן, ו-`-t <table>` משחזר רק אותה.
