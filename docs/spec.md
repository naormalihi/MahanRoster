# אפיון מערכת המשימות – תורנצ׳יק

גרסה 2.53.3 · 24.11.2026 · נאור מליחי

המסמך מתאר את המערכת כפי שהיא עובדת היום, את הכללים שלה ואת ההחלטות שהתקבלו בדרך. צילומי המסך מגרסה 2.47, ממצב ההדגמה עם נתונים פיקטיביים.

## 1. מטרה, היקף והנחות יסוד

תורנצ׳יק משבצת 100–500 עובדים מכמה מסגרות למשימות שהבסיס מקצה ליחידה, באופן הוגן ושקוף: לפי ניקוד מצטבר, כללי זכאות ואילוצים. המערכת רצה באינטרנט על שירותי ענן בשכבה החינמית, ופתוחה לכל אנשי היחידה – מהטלפון ומהמחשב.

**בתוך ההיקף:** טעינת כוח אדם, פטורים, חסימות והיעדרויות, מטריצת פוטנציאל לבסיס, קליטת לוח המשבצות מהבסיס, שיבוץ אוטומטי עם עתודה, פרסום, תפעול שוטף אחרי הפרסום (הפעלת עתודה, הסרה, משימה שנוספה, הקפצה), חשבון אישי לעובד, בקשות, החלפות בין עובדים, התראות לטלפון, תדריכים, מסכי צפייה למפקדים, ומשוב על האפליקציה.

**מחוץ להיקף:** חיבור למערכות כוח אדם צבאיות, SMS ומייל, אפליקציה נייטיב, ואחסון מסמכים רפואיים, אבחנות, מספרים אישיים או מספרי זהות.

**הנחות יסוד:**

- היחידה שולחת לבסיס פוטנציאל – מי זכאי לאיזו משימה – והבסיס מחזיר לוח משבצות לפיו. היחידה משבצת שמות.
- מחזור הוא חצי שנה. הפוטנציאל נשלח והלוח מתקבל פעם במחזור.
- אחראי השיבוצים מחזיק את כל התהליך ואת ההגדרות. מפקדים צופים. עובדים מגישים בקשות ורואים את המשימות שלהם.
- הניקוד צמוד לעובד, לא למסגרת, ונספר בחלון מתגלגל של חצי שנה.

## 2. משתמשים, תפקידים והרשאות

כל משתמש נכנס בשם משתמש וסיסמה, ורואה רק את מה שנדרש לתפקידו. אין הרשמה חופשית: חשבונות סגל נוצרים על ידי אחראי השיבוצים, ועובד פותח חשבון בקוד הצטרפות אישי שאחראי השיבוצים הפיק לו.

| תפקיד | כניסה | מה רואה | מה עושה |
| --- | --- | --- | --- |
| אחראי השיבוצים | סיסמה + אימות דו-שלבי | הכל: כוח אדם, אילוצים, פוטנציאל, שיבוץ, לוח, הגדרות, יומן | כל התהליך וכל ההגדרות. אפשר יותר מאחראי שיבוצים אחד |
| ממלא מקום (מ"מ) | סיסמה + אימות דו-שלבי | כמו אחראי השיבוצים | כמו אחראי השיבוצים, בתוקף שהוגדר לו |
| מפקד יחידה | סיסמה + אימות דו-שלבי | כל נתוני היחידה, ומסך "נתוני היחידה" כדף הבית | צפייה בלבד, וטיפול בהצעות ובמשוב |
| מפקד מסגרת | סיסמה + אימות דו-שלבי | הלוח, הטיוטה והפוטנציאל של כל היחידה – בלי פרטים אישיים; פרטים אישיים (ת"ש, פטורים, היעדרויות, אילוצים, טלפון) רק של המסגרת שלו | צפייה, ועדכונים מנהלתיים לעובדי המסגרת שלו: טלפון, מטווח, תפקידי הקלה וקודי הצטרפות. מקבל התראות לידיעה על עובדי המסגרת |
| עובד | סיסמה (אימות דו-שלבי רשות) | המשימות שלו, הניקוד שלו, הבקשות שלו והלוח המפורסם | בקשות, החלפות, "ראיתי", משוב |
| צפייה משותפת | סיסמה משותפת | הלוח המפורסם בלבד | כלום. ננעל כשלכל העובדים יש חשבון אישי |

- **סגל שעושה משימות:** חשבון של אחראי השיבוצים, מ"מ או מפקד שמשויך לרשומת עובד מקבל גם את תפקיד "עובד". יש לו תפריט "שלי" עם "המשימות שלי" ו"הבקשות שלי", החלפות והתראות כמו כל עובד, ובדף הבית "המשימה הבאה שלך". אחראי השיבוצים לא מאשר בקשת פטור של עצמו – אחראי השיבוצים או מ"מ אחר מאשר.
- **תפקיד לחשבון קיים:** עובד שהתמנה למפקד מסגרת מקבל תפקיד נוסף בחשבון שלו, בלי חשבון שני. אפשר גם להסיר תפקיד. תפקיד "עובד" נקבע לפי השיוך לעובד.
- **אין נציג מסגרת, ומפקד המסגרת לא חלק מהתהליך.** בגרסה 2 העובד מגיש בעצמו, ולכן נציג המסגרת ייתר את עצמו. מפקד המסגרת לא מאשר, לא בוחר מחליף ולא מטפל בהחלפות – הוא צופה, ומקבל התראות לידיעה.
- **עובד שהשירות שלו הסתיים לא נכנס:** תאריך השחרור עבר (היום האחרון עוד נחשב) או שהוצא מהיחידה – הכניסה נחסמת עם הודעה, וחיבור שכבר פתוח מפסיק לקבל נתונים מהשרת. תפקיד סגל באותו חשבון ממשיך לפי התוקף שלו. חשבון נעול מקבל הודעה מתאימה.
- **אימות דו-שלבי:** חובה לסגל ולמפקדים (אפליקציית Authenticator). מי שהחליף טלפון – אחראי השיבוצים או מ"מ מאפסים לו את האימות בהגדרות › משתמשים: הוא מתנתק מכל המכשירים ומגדיר מחדש בכניסה הבאה. האיפוס נרשם ביומן ושאר הסגל מקבל עדכון. כשיש רק אחד שיכול לאפס, תמונת המצב ממליצה למנות עוד אחד.
- **סיסמה שנשכחה:** אין איפוס במייל. אחראי השיבוצים נותן סיסמה זמנית חדשה, ובכניסה הבאה המשתמש בוחר סיסמה.
- **מחיקת משתמש:** משתמש שלא ביצע פעולות נמחק; משתמש ששמו רשום על פעולות נסגר ומוסתר, ושם המשתמש מתפנה. אפשר למחוק מפקד מסגרת גם כשהוא עושה משימות (רשומת העובד נשארת), וגם אחראי השיבוצים – מלבד את עצמך, וכל עוד נשאר לפחות אחראי השיבוצים פעיל אחד.
- **שינוי שם משתמש:** כל משתמש משנה את שלו – בכניסה הראשונה, יחד עם בחירת הסיסמה, בלי הגבלה (השם שאחראי השיבוצים הקליד הוא רק התחלה); אחר כך מהתפריט, עם הסיסמה הנוכחית, פעם בשבוע. אחראי השיבוצים יכול לשנות לכל משתמש בהגדרות › משתמשים. אותם כללים כמו לשם חדש; הסיסמה, התפקידים והאימות נשארים, והכניסה הבאה בשם החדש. חשבון הצפייה המשותף לא משנה שם. נרשם ביומן.
- **המסגרת של מפקד מסגרת:** ברירת המחדל – לפי העובד המשויך לחשבון, ומתעדכנת לבד כשהעובד עובר מסגרת בטעינת כוח אדם. אחראי השיבוצים יכול לבחור מסגרת במפורש (לחיצה על התג), למשל למפקד שאינו ברשימת העובדים. מפקד בלי מסגרת רואה רק את מה שמשותף לכולם.
- **מסירת פרטי כניסה:** בחלון הסיסמה הזמנית ובמשתמש חדש – "העתקה", או וואטסאפ ישירות לעובד המשויך לפי הטלפון בכרטיס שלו (בלי טלפון – בחירת איש קשר).

## 3. מחזור העבודה מקצה לקצה

מחזור הוא חצי שנה (למשל דצמבר–מאי). הכל במחזור נעשה במסך **תכנון ושיבוץ**, שבו "מחזור בעבודה" נבחר פעם אחת בסרגל העליון. השלבים אוטומטיים: אין כפתור "לשלב הבא". כל שלב מסומן ✓ (בוצע), ! (דורש טיפול) או ○ (עוד לא), לפי מה שקרה בפועל, עם הערה קצרה.

| שלב | מסך | מתי נחשב בוצע |
| --- | --- | --- |
| הקמת המחזור | ניהול מחזורים | המחזור נוצר (שם, תאריכים, מועד סגירת אילוצים) |
| טעינת כוח אדם | כוח אדם › טעינה | נטען קובץ אחרי שהמחזור נוצר |
| אילוצים: איסוף | 1. אילוצים | עבר מועד הסגירה |
| אילוצים: אישור פטורים | 1. אילוצים | אין פטורים ממתינים בטווח המחזור |
| פוטנציאל | 2. פוטנציאל | הפוטנציאל חושב |
| טעינת לוח משימות | 3. טעינת לוח משימות | יש משבצות |
| שיבוץ: הרצה / טיוטה | 4. שיבוץ | המנוע רץ ויש טיוטה |
| תפעול | 5. תפעול | הלוח פורסם |
| סגור | לוח השיבוצים | עבר היום האחרון של מחזור שפורסם |

- **מועד סגירת האילוצים:** היום האחרון להגשת פטורים, חסימות והיעדרויות, עד 23:59. ברירת המחדל: 40 יום לפני תחילת המחזור (בהגדרות). אחראי השיבוצים משנה אותו עד הפרסום; הארכה של מועד שעבר פותחת שוב את האיסוף.
- **נעילה אחרי פרסום:** פוטנציאל, לוח המשימות והרצה מלאה נעולים. שינוי עובר דרך התפעול. חזרה אחורה – רק בביטול פרסום.
- **סרגל השלבים בטלפון:** שורה אחת עם חצים לשלב הקודם והבא ונקודה לכל שלב, צפה בתחתית המסך; לחיצה עליה פותחת את רשימת השלבים. אותו סרגל, באותו מקום, גם בין לשוניות ההגדרות.
- **שיוך משבצת:** משבצת שייכת למחזור שבו היא מתחילה. משימה שנוספת ידנית חייבת להתחיל בתוך המחזור.

![תכנון ושיבוץ – סקירה: סרגל השלבים, הצעד הבא ושלב המחזור](/spec/03-cycle.webp)

**לוח זמנים מומלץ** (T = תחילת המחזור): טעינת כוח אדם ופתיחת האיסוף ב-T-60, סגירת אילוצים ב-T-40, פוטנציאל לבסיס מיד אחרי, קליטת לוח המשימות ושיבוץ תוך כמה ימים מקבלתו, פרסום לפחות שבוע לפני T.

## 4. כוח אדם

### טעינת קובץ כוח אדם

- אחראי השיבוצים טוען את הייצוא של מערכת כוח האדם כמו שהוא. מסך מיפוי עמודות מזהה כותרות מוכרות ושומר את ההתאמה.
- **עמודות חובה:** מספר עובד, שם (שם מלא, או שם פרטי ומשפחה), דרגה, ומסגרת (או "נתיב מסגרת" שהיא מופיעה בו – "…/גף X/צוות Y"; הקידומת "גף" יורדת, והמסגרת נשמרת בשמה בלבד). עמודות רשות: סוג שירות, תאריך כניסה לקבע, מין, תאריך גיוס, תאריך שחרור (תת"ש), תוקף מטווח, משרת הורה, טלפון נייד.
- **מספר העובד מוצפן במכשיר:** הדפדפן מוודא שיש בו רק ספרות, מתעלם מאפסים מובילים (Excel נוטה להוריד אותם, כך ש-00123 ו-123 הם אותו עובד), והופך כל מספר למזהה מוצפן (HMAC-SHA256) עם "מפתח היחידה" שרק אחראי השיבוצים יודע. רק המזהה נשלח לשרת. העמודה מזוהה גם בשמות "מס' עובד" ו"מ.ע", וגם בשמות הקודמים של ת.ז. קובץ עם עמודת "מספר אישי" מקבל הודעה להחליף אותה במספר עובד.
- **מסגרות לטעינה:** הקובץ יכול לכלול יותר אנשים מהיחידה. אחרי מיפוי העמודות אחראי השיבוצים בוחר מה נטען, מתוך עץ: המסגרת העליונה (החלק הראשון של נתיב המסגרת) והמסגרות שמתחתיה, ליד כל שורה מספר הרשומות. רשומות שהנתיב שלהן לא כולל מסגרת משנה מופיעות כ"ישירות תחת המסגרת". הבחירה נשמרת בהגדרות לטעינה הבאה: מסגרת חדשה תחת מסגרת עליונה שמסומנת כולה נכנסת מעצמה, ומסגרת עליונה חדשה מסומנת "חדש בקובץ" ולא נבחרת. רשומות ממסגרות שלא נבחרו לא נטענות ולא נחשבות שגיאות.
- **מפתח היחידה:** נשמר רק כטביעה. מפתח שגוי לא יהפוך את כולם ל"חדשים" – המערכת מזהה שהוא לא תואם. מפתח שנשכח מוחלף ב"החלפת מפתח": טוענים את הקובץ המלא עם מפתח חדש, המערכת מתאימה עובדים לפי שם (ובודקת מסגרת, מין, גיוס ודרגה), ואחראי השיבוצים מאשר.
- **תצוגה מקדימה:** חדשים, שיצאו, ושינויים לאישור. שינוי אצל עובד קיים (דרגה, מסגרת, תאריכים) נטען רק באישור – שורה, הכל, או לפי שדה. שדה ריק בקובץ לא מוחק ערך קיים, ומה שהוזן ידנית (שח"ר, הקלה, דרגת מינוי, ת"ש, הורה) לא נדרס.
- **מי שיצא:** עובד שלא בקובץ מסומן לא פעיל – לא נמחק, וההיסטוריה שלו נשמרת.
- **מי שעבר מסגרת:** עובד קיים שהקובץ שם במסגרת שלא נבחרה לא מסומן לא פעיל מעצמו. הוא מופיע בהתראה ובלשונית "עברו מסגרת", עם המסגרת שלו עכשיו והמסגרת בקובץ, ואחראי השיבוצים מסמן את מי להוציא.
- **סוג שירות:** מעמודת סוג שירות; אם אין – מתאריך הכניסה לקבע ביום תחילת המחזור; אם אין גם אותו – לפי הדרגה (חובה 1–4 חובה, כל השאר קבע).

### הוספת עובד ידנית והוצאה מהיחידה

- **הוספת עובד:** טופס קצר לעובד אחד, בלי קובץ – שם, מספר עובד (מוצפן במכשיר), מסגרת, דרגה, שירות, מין, תאריכים, טלפון, שח"ר, תאריך תפקיד שני וזכאות ת"ש. עובד שכבר קיים לא נוצר פעמיים, ומי שיצא מוחזר עם ההיסטוריה שלו.
- **הוצאה מהיחידה:** בכרטיס העובד, מתאריך. המשימות שלו מאותו יום יורדות ומסומנות כמשבצות לאייש, והוא לא יכול להתחבר.
- **כמה עובדים יחד** (2.52): בסימון עובדים במסך כוח אדם – "מחיקת הנבחרים" (לסגל), עם שתי אפשרויות: **הוצאה מהיחידה** (ברירת המחדל) – כמו לעובד בודד, מתאריך, וההיסטוריה נשמרת; או **מחיקה לצמיתות** – העובד וכל מה שעליו (אילוצים, פטורים, חסימות, ניקוד, קוד הצטרפות, וחשבון עובד בלבד) נמחקים, ומשתמש סגל שמקושר אליו נשאר בלי הקישור. עובד עם משימות בלוח שפורסם לא נמחק לצמיתות – הוא מופיע ברשימת "לא נמחקו". למחיקה לצמיתות מקלידים את מספר הנבחרים, והיא נרשמת ביומן הביקורת.

### כרטיס העובד ומסך כוח אדם

- טבלה עם חיפוש וסינון (מסגרת, דרגה כולל מינוי, הקלה, פטור, שירות, מטווח), מיון לפי כל עמודה. בטלפון – כרטיס לכל עובד וסינון מתקפל.
- **בחירה של כמה עובדים:** תיבת סימון ליד כל עובד שאפשר לעדכן, ל"עדכון מטווח לנבחרים" ולקודי הצטרפות. בטלפון כל הפס שבצד הכרטיס מסמן (שאר הכרטיס פותח את העובד), ופס "נבחרו N" נשאר בתחתית המסך. "הצגת לא פעילים" פתוח לכולם.
- **הטבלה במחשב:** עמודת השם (עם עיפרון העריכה) נשארת בצד ימין כשגוללים הצידה, ולחיצה על שורה פותחת את העובד. הכותרות נשארות למעלה בגלילה.
- **תיקון ניקוד** (2.53, אחראי השיבוצים ומ"מ): בחלון העובד, תחת "ניקוד" – "ניקוד נוכחי חדש" או "תוספת / הפחתה", עם סיבה חובה (עד 200 תווים), בלי הגבלת ניקוד – גם ניקוד התחלתי גבוה. התיקון שייך למחזור הנוכחי (או הבא, אם אין נוכחי) ונספר מיד: בניקוד הנוכחי בטבלה (עם הסימן ✎; בין מחזורים – הניקוד הנוכחי הוא הניקוד שממנו מתחילים את המחזור הבא, ותיקון למחזור הבא מופיע גם בו וגם בניקוד העתידי), בניקוד הקודם של המחזור – ולכן באיזון ובהרצת השיבוץ הבאה – ובניקוד המצטבר של המחזורים הבאים, כמו נקודות ממשימות. נשמר גם כשתמונת המחזור נבנית מחדש. בחלון: רשימת התיקונים (מי, מתי, כמה ולמה) וביטול. הכל ביומן.
- **מפקד מסגרת – עדכונים מנהלתיים** (2.49): לעובדי המסגרת שלו בלבד – טלפון, תאריך מטווח (גם לכמה יחד), תפקידי הקלה (ר"צ, כונן מבצעי – מי ומתי; המקדמים בהגדרות של אחראי השיבוצים), קודי הצטרפות, ו"שליחת וואטסאפ" למשובצים בלי חשבון. בכרטיס העובד פתוחים לו רק השדות האלה. פטורים, ת"ש, הקלות, דרגת מינוי, הורה, שח"ר, העברה והוצאה מהיחידה – אצל אחראי השיבוצים, כי הם דורשים אסמכתא. השרת מקבל ממנו רק את השדות האלה, דרך פונקציות שבודקות שהעובד במסגרת שלו; הטבלה עצמה סגורה לו. הכל ביומן; שינוי בתפקיד הקלה (משפיע על הניקוד) נשלח לאחראי השיבוצים בהתראה.
- עמודות: שם, דרגה, מסגרת, שירות, תום שירות, ת"ש, **ניקוד נוכחי** (פתיחה ועוד המחזור שהיום בתוכו) ו**ניקוד עתידי** (המחזור הבא, מפורסם או טיוטה), משימת חג, חשבון (שם משתמש / הוזמן / נשלח / קוד פג). בראש המסך – ממוצע וטווח לחובה ולקבע.
- כרטיס העובד: פרטים, טלפון, תוקף מטווח (ריק = נחשב בתוקף), הקלה, דרגת מינוי, משרת הורה ות"ש (סימון ידני גובר על הקובץ), שח"ר, תפקיד שני, פטורים בתוקף ועתידיים, והוצאה מהיחידה.
- **טלפון:** גלוי לאחראי השיבוצים, למפקד המסגרת (למסגרת שלו) ולמפקד היחידה. ביומן השינויים נרשם השינוי בלי המספר.

### קודי הצטרפות

- אחראי השיבוצים בוחר עובדים ← "קודי הצטרפות" (תוקף 7–60 יום). הקוד מוצג פעם אחת ונשמר רק כטביעה; קוד חדש מבטל קודם.
- שליחה: וואטסאפ לכל עובד עם הודעה מוכנה וקישור שממלא את הקוד, או הדפסה לפי מסגרת – כרטיס עם QR לכל עובד לגזירה. המסך מסמן "הוזמן · לא נשלח" מול "נשלח".
- העובד בוחר "יש לי קוד הצטרפות", מזין את הקוד ובוחר שם משתמש וסיסמה.

## 5. זכאות, אילוצים ופוטנציאל

### כללי זכאות

הזכאות של כל עובד לכל משימה מחושבת מכללים, ומשמשת גם לפוטנציאל לבסיס וגם כאילוץ קשיח בשיבוץ.

- **סוג שירות, דרגות ומגדר:** לכל סוג משימה – מי יכול לבצע (כולם / חובה / קבע), רשימת דרגות (בלי בחירה = כל הדרגות) ומגדר. רשימת דרגות שמגיעה מלוח המשימות גוברת על זו של הסוג באותה משבצת.
- **פטור שפוטר ופטור שמזכה:** לכל סוג פטור – מאילו משימות הוא פוטר ובאילו הוא מזכה. משרת הורה ובעל פטור מזכה מבצעים רק את המשימה המזכה (ממלכת יום). פטור רפואי פוטר מהכל חוץ ממלכת יום, שבה הוא מזכה, גם בחובה.
- **שח"ר:** לכל סוג משימה – לא לשח"ר / גם לשח"ר / רק לשח"ר. עובד שח"ר בחובה זכאי רק לסוגים שמתאימים לשח"ר. "רק לשח"ר" (למשל מטבח) פתוח רק להם. בקבע – פטור עד שנה וחצי מהכניסה לקבע. קצין – אין שח"ר.
- **ת"ש (זכאות 3–7):** מספר הלילות בשבוע שהעובד חייב לישון בבית. הוא לא ישובץ ליותר מ-7 פחות הזכאות לילות בבסיס בשבוע, לא במשימה ארוכה אחת ולא בצירוף. לכל סוג משימה: לפי שעות לילה (ברירת מחדל), מתאימה לת"ש (לא נחשבת לילה בבסיס) או לא מתאימה. משבצת שהבסיס סימן "ת"ש 7" ניתנת קודם לבעלי ת"ש 7.
- **מטווח:** משימה שדורשת נשק דורשת מטווח בתוקף ביום המשימה. עובד בלי תאריך מטווח נחשב בתוקף. רק תאריך שהוזן חוסם – מהיום שבו פג.
- **תקופת הכשרה לעובד חדש:** 90 יום (בהגדרות, 0–365) מיום ההצטרפות, בלי שיבוץ אוטומטי. ראו "עובד חדש" בפרק הניקוד.
- **תאריכי שירות:** לא לפני גיוס ולא אחרי שחרור.
- **עובד בכמה אוכלוסיות:** פטור או הקלה שפוטרים גוברים, אחריהם הורה ופטור מזכה, אחריהם דרגה ושירות.

### פטורים, חסימות והיעדרויות

- **פטור:** סוג מהקטלוג וטווח תאריכים. אין צירוף מסמכים ואין סיבה בטקסט חופשי. העובד מגיש מהטלפון (או אחראי השיבוצים בשמו), מציג את האסמכתא לאחראי השיבוצים מחוץ למערכת, ואחראי השיבוצים מסמן "אסמכתא נבדקה" ומאשר או דוחה עם נימוק. פטור יכול להיות חלקי – לסוגי משימה או לחלונות שעות. ת"ש 7 הוא סוג פטור שתמיד חל על לילות.
- **אחרי מועד הסגירה:** חסימות והיעדרויות רק דרך אחראי השיבוצים; בקשת פטור מסומנת דחופה. פטור שמאושר אחרי הפרסום משחרר את המשימות של העובד בטווח – מבצע מוחלף בעתודה שלו, עתודה יורדת.
- **חסימת תאריך:** יום שבו העובד לא ישובץ (אירוע משפחתי). מכסה: אחת בחודש (בהגדרות). לא דורשת אישור, רק בחלון האיסוף ובמסגרת המכסה.
- **היעדרות:** חופשה, קורס, יציאה לחו"ל, מחלה ועוד – טווח תאריכים. היעדרות "לא מבחירה" (קורס, מחלה) של 7 ימים ומעלה מזכה בזיכוי זמינות (פרק 7).
- **זמינות מהתדריך:** כשלמשבצת יש תדריך לפני התחלתה, היעדרויות וחסימות נבדקות משעת התדריך.
- **תבנית למסגרות:** אקסל עם עובדי המסגרת לחסימות והיעדרויות, לטעינה מרוכזת.
- **בקשות בלי מחזור:** בקשה לתאריכים שעוד אין להם מחזור נשמרת, ותמונת המצב מתריעה עליה.

![1. אילוצים – פטורים ממתינים לאישור, עם אסמכתא, סטטוס ואישור/דחייה](/spec/04-constraints.webp)

### מטריצת הפוטנציאל

- עובד מול קטגוריית משימה. בכל תא: 1 (זכאי כל המחזור), ריק (לא זכאי), או חלק – ימי הזמינות חלקי ימי המחזור (היעדרות של חודשיים מתוך שישה = 0.67). ימי הכשרה וימים אחרי שחרור לא זמינים.
- מעבר עכבר מסביר למה לא זכאי. אחראי השיבוצים מתקן תא עם נימוק, והתיקון מסומן.
- **למה לא 1:** לחיצה על תא עם שבר מפרטת את הימים החסרים לפי סיבה, עם תאריכים – לפני הגיוס, אחרי השחרור, חדש ביחידה (90 יום מהכניסה), היעדרות (עם הסוג), פטור (עם הסוג). סיבות חופפות מסומנות. נפתח לקריאה גם אחרי שהמחזור ננעל.
- "זמינות לפי שבוע" – כמה זמינים לכל קטגוריה ביום הכי חלש בשבוע, עם צבע לשבועות החלשים.
- ייצוא לבסיס: סיכום לכל קטגוריה ורשימה שמית.
- כל הרצת שיבוץ מחשבת קודם פוטנציאל מחדש. אחרי פרסום הפוטנציאל נעול.

![2. פוטנציאל – המטריצה עם שורת הסיכום, ערכים חלקיים ותיקונים](/spec/05-potential.webp)

### קבוצות הוגנות

עובד מושווה רק למי שיכול להתחלק איתו בעומס. בתוך כל אוכלוסייה (חובה / קבע), שתי קטגוריות מחוברות אם יש עובד שפתוחות לו שתיהן, והקבוצה היא רכיב קשירות. כך "חובה 1–4" (רס"ר ושמירות) ומובילים בחובה (קצין תורן, מפקד שער) הם שתי קבוצות, לכל אחת ממוצע משלה. בכל מקום שנאמר "ממוצע", הכוונה לממוצע קבוצת ההוגנות.

## 6. קטלוג המשימות ולוח המשימות

### קטלוג המשימות

בהגדרות › קטלוג משימות, לכל סוג משימה:

| שדה | משמעות |
| --- | --- |
| שם וקטגוריה | הקטגוריה היא עמודה בפוטנציאל (הגנ"ש, קצין תורן, מפקד שער, ממלכת, שמירות חובה, רס"ר, משימות חיליות, מפקד תורן, מטבח). את שמות הקטגוריות אפשר לשנות ולהוסיף |
| משקל | הניקוד של המשימה כולה, לא תלוי במספר הימים (אמ"ת של שבוע = 13). שינוי חל על שיבוצים חדשים בלבד ונרשם בהיסטוריית המשקלים |
| שעות | התחלה וסיום ברירת מחדל, ואפשר שעות שונות לפי יום בשבוע וליום שאחרי חג ("+1" = הסיום למחרת). למשל מפקד תורן: ראשון 06:00 עד 08:00 למחרת, חמישי 08:00–18:00 |
| צבע | בלוח ובהדפסה |
| תדריך והתייצבות | ראו למטה |
| מי יכול לבצע | סוג שירות, דרגות, מגדר, שח"ר, ת"ש |
| נשק | דורשת מטווח בתוקף |
| משימת שבת | המשקל כבר כולל סוף שבוע – בלי תוספת סוף שבוע |
| המשקל כולל חגים | למשימה שמתמחרת תקופה שלמה (אמ"ת, הגנ"ש) – בלי תוספות לוח החגים. היא עדיין נחשבת משימת חג לחלוקת החגים |
| מזכה | פתוחה גם למשרתי הורה ולבעלי פטור מזכה |
| פעילה | משימה לא פעילה לא משובצת |

- סוג משימה נמחק רק כשאין לו משבצות, אילוצים או פטורים; אחרת הופכים אותו ללא פעיל.
- **הקפצה מיוחדת** (פרק 9) נשמרת על סוג נסתר, כדי שהקטלוג יישאר נקי.

### תדריך והתייצבות

כל סוג משימה יכול לשאת את מה שכתוב בשלט "זמני משימות" של הבסיס:

- **סוג:** תדריך, התייצבות, או "תדריך לפי הזימון" (בלי שעה קבועה, למשל מפקד תורן).
- **מתי:** ביום המשימה, יום לפני, או ביום מסוים בשבוע שלפני ההתחלה (למשל "ביום שלישי שלפני" – מתאים גם לשמירות שמתחילות בכל יום). המועד המחושב תמיד לפני ההתחלה, ועד 7 ימים.
- **שעה, מיקום, איש קשר וטלפון, הערה לעובד** (למשל "לא מאושרות החלפות בעת ביצוע המשימה!"). איש הקשר והטלפון מוצגים רק לעובד המשובץ.

המועד של כל משבצת מחושב מהקטלוג; שעה ומקום שנכתבו במשימה עצמה (בלוח המשימות או בתפעול) גוברים. הקטלוג מולא מהשלט: מטבח – התייצבות 08:30; רס"ר – התייצבות בשק"ם 08:30; רס"ר הקלת ת"ש – מש"ק תורנים 09:00; קצין הגנ"ק – התייצבות 09:00; קצין תורן – תדריך 09:00; ממלכת יום – תדריך טלפוני 11:00; שמירות חובה – תדריך בשלישי שלפני 13:00; מפקד שער ומשימות קבע – תדריך בשלישי שלפני 09:30; מפקד תורן – לפי הזימון.

![קטלוג משימות – עריכת משימה עם קוביית "תדריך והתייצבות"](/spec/12b-catalog-briefing.webp)

### טעינת לוח משימות

- **הקובץ:** נדרשות שתי עמודות – **מועד** ו**סוג משימה** – ועמודת **הערה** אופציונלית (גם "דגשים"; לא "הערות", שבקובץ של הבסיס מחזיקה טלפונים). שורה = משבצת עם מבצע ועתודה. כל השאר נגזר: השעות מסוג המשימה (לפי יום בשבוע), גרסת השבת והחגים מהתאריך, ומי יכול לבצע מהסוג. עמודות אחרות בקובץ לא נקראות – גם לא מסגרת, מבצע ועתודה, שהם נתון ממערכות המידע ולא הקצאה. יש תבנית ריקה להורדה.
- **שמות מהבסיס:** שם שהמערכת לא מכירה ("אמ"ת חרבית", "ש.ג דרום 7-11") פותח מיפוי לסוג בקטלוג, והמיפוי נשמר לפעם הבאה (הגדרות › שמות מהבסיס). אפשר לסמן "לא לקלוט", או ליצור מהשם סוג חדש. הבסיס משתמש באותו שם לחול ולשבת – משבצת שמתחילה בשישי או בשבת עוברת לגרסת השבת לבד.
- **חג:** נקבע תמיד לפי לוח החגים, לא לפי הקובץ.
- טעינה מחדש מחליפה משבצות של הקובץ הקודם שעוד לא שובצו – כולל הערות שנערכו ידנית.

### הערה למשימה (2.51)

- **מקור:** עמודת "הערה" בלוח המשימות, או כתיבה ידנית. עד 300 תווים, ירידות שורה נשמרות. מוצגת כפי שנכתבה – לא נקראים ממנה תדריך או מגדר. גלויה לכל מי שרואה את הלוח, ולכן בלי טלפונים או פרטים אישיים.
- **קליטה:** בתצוגה המקדימה עמודת "הערה", ובסיכום "N משבצות · M עם הערה".
- **איפה רואים:** בלוח השיבוצים – ישירות על המשימה (💬), מתחת לשורת התדריך, ובהדפסה; החיפוש בלוח מוצא גם מילים מההערה. ב"המשימות שלי" – מתחת לתאריך. בהודעת הוואטסאפ – שורה "הערה: …". בתזכורת "משימת מחר" – בסוף, מקוצרת ל-60 תווים. ובקובץ היומן.
- **עריכה:** אחראי השיבוצים ומ"מ, בחלון המשימה (מהטיוטה, מהתפעול או מלוח השיבוצים): "הוספת הערה" / "עריכת הערה". ב"משימה חדשה" בתפעול – שדה הערה. אחרי פרסום, שינוי בהערה שולח למבצע ולעתודה התראה ("עודכנה הערה למשימה"). הכל ביומן.

## 7. מודל הניקוד

### הנוסחה

```latex
P = (W + D) \times S
```

- **W – משקל:** של המשימה כולה, מהקטלוג.
- **D – תוספת יום:** הערך הגבוה מבין התוספות שחלות על אחד מימי המשימה, **פעם אחת**. תוספות לא מצטברות. למשל סוף שבוע +3, ערבי חג מרכזיים +6, חג +3.
- **S – הקפצה:** ×1.3 לעובד ששובץ למשימה פחות מ-72 שעות לפני תחילתה (עתודה שהופעלה, מחליף, משימה שנוספה). מי שתוכנן מהפרסום הראשון לא מוקפץ. החלפה בין עובדים לעולם לא נחשבת הקפצה.

דוגמאות: מטבח (4) ביום רגיל = 4; בשישי = 7; בערב ראש השנה = 10; בערב ראש השנה, כהקפצה = (4+6)×1.3 = 13. אמ"ת (13, המשקל כולל חגים) = 13 גם בחנוכה.

**ניקוד מנורמל לפי תפקיד:** עובד בתפקיד מקל מקבל ניקוד מוגדל, כך שעושה פחות משימות באותו ניקוד:

```latex
S_{norm} = \sum_i \frac{P_i}{F_i}
```

F – מקדם ההקלה ביום שבו המשימה מתחילה: עובד רגיל 1, כונן מבצעי 0.7, ראש צוות 0.5. לעובד עם שני תפקידים – המקדם הנמוך, בלי מכפלה. מקדם 0 אסור: פטור מלא מנוהל כפטור.

### תוספות היום

התוספות הן רשימה פתוחה בהגדרות › מקדמי ניקוד. לכל תוספת שם, ערך ותנאים, והיא חלה על יום שבו כל התנאים מתקיימים:

- **סוג יום בלוח השנה** – חג, ערב חג, חג מרכזי (ראש השנה, יום כיפור, פסח) וערבו, יום זיכרון, או סוג יום שאחראי השיבוצים הוסיף.
- **ימים בשבוע** – למשל שישי ושבת.
- **חלון שעות** – למשימה קצרה מ-24 שעות שרוב שעותיה בחלון (לילה).
- **טווח תאריכים** – תקופה מוגברת.
- **לא למשימות שבת** – כי המשקל שלהן כבר כולל סוף שבוע.

**לוח חגים:** חגים 2026–2035 נטענים מראש (לוח עברי), עם עריכה ידנית. בהגדרות › לוח חגים יש טבלה – לכל חג שורה ולכל יום בחג תא (ערב חג, החג, חול המועד) – שבה כותבים תוספת לחג מסוים. מועדים שאינם שבתון (חנוכה, פורים, צומות, ל"ג בעומר ועוד) מופיעים בלוח ליד התאריך, ותוספת חלה עליהם רק אם נקבעה להם בטבלה. חול המועד לא נחשב חג לאיזון סופי שבוע.

![איך מחושב הניקוד – העמוד שכל עובד רואה: הנוסחה, דוגמאות והמספרים מההגדרות](/spec/15-scoring.webp)

### הניקוד המצטבר

- **חלון מתגלגל:** חצי השנה שלפני תחילת המחזור. נספרות משימות שנשארו בלוחות שפורסמו – מבצע משובץ או שביצע, ועתודה שהופעלה. משימה שירדה, הוחלפה או בוטלה לא נספרת. עתודה שלא הופעלה לא מזכה בניקוד, אבל נספרת לאיזון העתודות.
- **ניקוד צפוי** = הניקוד בחלון + מה שהטיוטה מקצה לעובד במחזור. המנוע מאזן את הניקוד הצפוי.
- **זיכוי זמינות:** עובד שנמצא מחוץ ליחידה בחלק מהמחזור שלא מבחירה – לפני גיוס, אחרי שחרור, תקופת הכשרה, פטור מלא, היעדרות לא מבחירה של 7 ימים ומעלה – מקבל על כל יום כזה את העומס היומי הממוצע של הקבוצה. מי שהגיע אחרי שליש מהמחזור נושא בערך שני שלישים מהעומס. היעדרות מבחירה (חופשה, חו"ל) לא מזכה.
- **טווח הוגנות:** עד 20% (בהגדרות) מממוצע הקבוצה, ולפחות חצי נקודה. מה שמחוצה לו לא בהכרח בעיה – ראו "איזון" בפרק 8.

### עובד חדש

- **ניקוד פתיחה:** ממוצע קבוצת ההוגנות שלו, בלי החדשים האחרים (אין עמיתים – ממוצע האוכלוסייה). כך הוא לא סופג את כל המשימות. הניקוד מתוארך לתחילת המחזור, כדי שייספר בחלון.
- **תקופת הכשרה:** 90 יום מיום ההצטרפות, בלי שיבוץ אוטומטי, עם זיכוי זמינות על הימים האלה. יום ההצטרפות: המאוחר מבין היום שבו נוסף ותחילת המחזור הראשון שלו.
- **שיבוץ ידני בתקופת ההכשרה** נחשב הקפצה (×1.3) – כפיצוי. בחלון השיבוץ הידני הוא מסומן "חדש ביחידה" עם הסבר.
- **אותו כלל** חל על עובד בתפקיד שני (חתם על המשך קבע – אחראי השיבוצים מזין תאריך) ועל חוזר מהיעדרות של יותר מ-3 חודשים שלא מבחירה: הניקוד מועלה לממוצע אם הוא מתחתיו.

## 8. מנוע השיבוץ

### אילוצים קשיחים (לא מופרים לעולם)

- זכאות: שירות, דרגות, מגדר, פטורים, שח"ר, ת"ש, נשק ומטווח, תקופת הכשרה, תאריכי שירות.
- פטור בתוקף, חסימה והיעדרות.
- אין שתי משימות חופפות לאותו עובד – מבצע או עתודה.
- מנוחה בין משימות לפי הקטלוג.
- עתודה לכל מבצע. בחובה – מאותה מסגרת כמו המבצע שלה. עתודה היא לא המבצע.
- תקרה חודשית, אם הוגדרה (ברירת מחדל: ללא).

### אילוצים רכים (ממוזערים, לפי משקלים)

- הפער בניקוד המנורמל מממוצע קבוצת ההוגנות.
- איזון סופי שבוע וחגים, ואיזון מספר הפעמים כעתודה.
- **חג קודם למי שלא עשה:** משימה בחג ניתנת קודם למי שלא עשה חג בשנה האחרונה, ובמחזור – למי שעוד לא קיבל.
- **לא בשבועות רצופים:** מבצע בשני שבועות רצופים (ראשון–שבת) עולה כ-3 נקודות הוגנות, עתודה באחד מהם כ-1.
- משבצת "ת"ש 7" למי שאינו ת"ש 7 – כ-10 נקודות הוגנות.

### איך הוא רץ

- **פותר:** Python עם Google OR-Tools CP-SAT, ב-GitHub Actions. ההרצה מופעלת מהמסד עצמו (pg_net) כשנרשמת משימת שיבוץ.
- **חודש אחר חודש:** כל חודש מתחיל מהניקוד, הסופי"שים והעתודות שהשאירו החודשים שלפניו. מחזור של מאות משבצות נגמר בדקות.
- **ליטוש:** בסוף, קבוצה שנשארה לא מאוזנת מקבלת חלוקה מחדש על פני כל המחזור; התוצאה נשמרת רק אם היא טובה יותר וכל הכללים נשמרים.
- **בודק עצמאי:** לפני שמירה, קוד נפרד מוודא שאף אילוץ קשיח לא הופר. תוצאה שמפרה – לא נשמרת, וממצאי הבדיקה מוצגים בשמות.
- **תמיד יש תוצאה:** שיבוץ מפורסם הוא נתון, לא החלטה – לא מכשיל הרצה. משימה שלא אוישה מציגה למה (מי לא זכאי, מי עסוק, מי בתקרה, מי נחסם בכלל המסגרת). אם המנוע נכשל, הוא מסביר בעברית איזה כלל חוסם.
- **עובד שירד ממשימה** (הוסר עם סיבה, הוחלף בעתודה, שוחרר בפטור) לא מוצע שוב לאותה משימה.

### עדכון שיבוץ מול שיבוץ מלא מחדש

כשיש טיוטה, הכפתור הראשי הוא **עדכון שיבוץ**: מחשב פוטנציאל מחדש ויוצא מהטיוטה הנוכחית. חודש שבו הכל עדיין חוקי ומאויש נשאר; בחודש אחר מוסרים שיבוצים שכבר לא חוקיים והמנוע משלים, עם הטיוטה כנקודת התחלה; בסוף ליטוש. שינויים ידניים נשמרים. **שיבוץ מלא מחדש** הוא כפתור משני, עם אישור – מאפס, אחרי שינוי גדול.

### מסך השיבוץ

- כרטיס הרצה עם מצב (מוכן / רץ / טיוטה), התקדמות (כמה שובצו מתוך כולן, באיזה חודש, ליטוש) וזמן משוער.
- קוביות: **חסרים**, **איזון** (תקין, או כמה בעיות), **בלי משימה במחזור**, **שינויים ידניים** – כל אחת מסננת את הרשימה.
- שתי תצוגות עם חיפוש אחד: **לוח** (לפי ימים) ו**עובדים** (קבוצות הוגנות, פס לכל עובד מול הממוצע).
- **חלון עובד:** קודם, זיכוי, במחזור וצפוי; מה משפיע על השיבוץ שלו (היעדרויות, פטורים, ת"ש, הקלה, הורה, שח"ר, מטווח, חג, תאריכי שירות); כשירות לכל קטגוריה; ו"למה מעט משימות?" לפי סיבה.
- **עריכה ידנית:** לחיצה על משבצת פותחת מועמדים – פנויים וזכאים קודם, לפי ניקוד, ולכל מי שלא מתאים הסיבה. עובד שמשובץ באותו זמן לא ניתן לבחירה (גם השרת דוחה); מנוחה קצרה היא אזהרה שאפשר לעקוף עם סיבה. כל שינוי דורש נימוק ונרשם ביומן.
- ליד כל שיבוץ – הסבר ("הניקוד שלו 12.5 לעומת ממוצע 14"), שגם העובד רואה.

### איזון – מה נחשב בעיה

עם משימה אחת או שתיים לעובד במחזור, משימה אחת לבדה מזיזה עובד רחוק מהממוצע – זה לא חוסר הוגנות אלא האופן שבו העומס מתחלק במשימות שלמות, והניקוד המצטבר מאזן אותו במחזור הבא. לכן המסך מבחין בין ארבעה מצבים. הניקוד שמשווים הוא המצטבר (קודם + זיכוי + המחזור), מול ממוצע מי שזכאים לאותן קטגוריות בקבוצת ההוגנות:

| מצב | מתי | איך מוצג |
| --- | --- | --- |
| **בטווח** | קרוב לממוצע (טווח ההוגנות שבהגדרות) | לא מוצג |
| **פער של עד משימה אחת** | מחוץ לטווח, אבל לא יותר מהניקוד של המשימה הכבדה ביותר שפתוחה לו בטיוטה (כולל תוספת יום והקפצה) | שורה אפורה: "יתאזן במחזור הבא" – לא בעיה |
| **פער מצטבר** | גם עם המחזורים הקודמים, יותר ממשימה אחת מהממוצע | **בעיה** |
| **שיבוץ לא לפי התור** | משימה שעוד לא הסתיימה ניתנה לעובד, כשעובד מאותה קבוצה היה פנוי וזכאי (אותה בדיקה כמו בשיבוץ ידני) ונמוך ממנו בניקוד המצטבר ביותר ממה שהמשימה שווה | **בעיה**, בפאנל נפרד עם שני השמות והניקוד |

הקובייה "איזון" סופרת רק בעיות; "רק בעיות" מסנן את הרשימה; בחלון העובד כתוב אם הפער שלו "יתאזן במחזור הבא" או "צריך לבדוק".

## 9. פרסום ותפעול שוטף

### פרסום וביטול פרסום

- **פרסום:** אפשר גם כשיש משבצות לא מאוישות – אחראי השיבוצים מאשר אזהרה, והן מסומנות באדום. בפרסום כל עובד מקבל התראה אחת ("יש לך 3 משימות ו-2 עתודות, הראשונה …"), והינשוף חוגג.
- **ביטול פרסום:** רק אחראי השיבוצים, רק לפני שהמחזור התחיל. השיבוצים חוזרים לטיוטה כמו שהם, הלוח נעלם, והעובדים מקבלים הודעה. חלון אזהרה מסביר שמי שהדפיס לא יקבל עדכון. נרשם ביומן.

### מסך התפעול

אחרי הפרסום כל שינוי נעשה במסך **5. תפעול** או ישר מהלוח (לחיצה על משימה פותחת את הפעולות שלה):

- **משימות שממתינות לשיבוץ:** משימה שנוספה, או שחסר בה מבצע או עתודה (אחרי הפעלה או הסרה). "שיבוץ" מריץ את המנוע על הממתינות בלבד – כל מה שפורסם קבוע – ואחראי השיבוצים מאשר את ההצעה. אפשר גם לשבץ ידנית ישר ללוח.
- **משימה חדשה במחזור:** סוג, מועד (בתוך המחזור), מבצעים ועתודות.
- **הקפצה מיוחדת:** משימה מתפרצת שלא בקטלוג – שם, ניקוד למבצע (0.5–100, לכל המשימה, בלי תוספות ובלי ×1.3), מי יכול לבצע ודרגות. מופיעה בשמה בלוח עם תווית ניקוד. עד שהיא מתחילה אפשר לשנות שם וניקוד, ומי ששובץ מקבל את החדש.
- **הפעלת עתודה:** המבצע יורד והעתודה הופכת למבצע. במשימה של כמה יממות בוחרים מאיזו יממה, וכל אחד מקבל ניקוד על היממות שלו. העתודה מקבלת התראה עם "קיבלתי". אחרי ההפעלה המשימה ממתינה לעתודה חדשה. **ביטול הפעלה** אפשרי עד שהמשימה מתחילה (לא כשלמבצע פטור מאושר) – שניהם מקבלים הודעה.
- **הסרה:** מבצע או עתודה ממשימה שלא התחילה, עם סיבה – העובד מקבל התראה, הניקוד יורד, והמשימה עוברת לממתינות.
- **מחיקת משימה:** גם אחרי פרסום וגם כשיש עליה אנשים, עד שהיא מתחילה, עם סיבה. מי שעליה יורד ומקבל הודעה. נרשם ביומן.
- **חיפוש** משימות לפי שם עובד, משימה או תאריך.
- **וואטסאפ:** "שליחה למי שאין לו חשבון" – כל עובד בלי חשבון מקבל הודעה אחת עם כל המשימות שלו וקוד הצטרפות. ליד כל משימה – הודעה בלחיצה, עם התדריך ובקשה לענות "קיבלתי".

![5. תפעול – משובצים בלי חשבון עם וואטסאפ, משימות שממתינות לשיבוץ, והפעלת עתודה עם חיפוש](/spec/08-operate.webp)

### אישור קבלה ("ראיתי")

- ליד כל משימה חדשה או שהשתנתה – "ראיתי", ובאנר "ראיתי את כולן". מי שקיבל משימה בהחלפה נחשב כמי שאישר.
- מי שלא אישר מקבל תזכורת אחרי 48 שעות; 24 שעות לפני המשימה מפקד המסגרת מקבל עדכון. שני הזמנים בהגדרות (0 = כבוי).
- בתמונת המצב של אחראי השיבוצים: **לא אישרו – 72 השעות הקרובות**, עם וואטסאפ, חיוג ו"וידאתי בטלפון".

### החלפות בין עובדים

- ממשימה שלו, עד 24 שעות לפני: **"מישהו לוקח ממני"** (העברה) או **"מתחלפים"** (הדדית).
- מוצגים רק מי שבאמת יכולים – זכאות, מנוחה, פטורים, היעדרויות ומשימות חופפות – ויש להם חשבון.
- העובד השני מאשר מההתראה או מ"המשימות שלי", וההחלפה מתבצעת מיד. **בלי אישור סגל.** הנקודות עוברות למי שעושה. אחראי השיבוצים מקבל התראה, ובתמונת המצב רואים את ההחלפות האחרונות.

## 10. העובד

### המשימות שלי

דף הבית של העובד, מותאם לטלפון:

- ברכה לפי השעה והמשימה הבאה; בלי משימות קרובות – ינשוף ישן.
- כל המשימות שלו בלוחות שפורסמו (טיוטה לא נראית לו): מבצע או עתודה, מועד, ניקוד.
- בלחיצה: התייצבות, תדריך (מועד ומקום, או "לפי הזימון"), איש קשר עם טלפון בלחיצה, ההערה מהקטלוג, ציוד, ו**למה שובצתי**.
- "ראיתי" לכל משימה חדשה או שהשתנתה, ובקשות החלפה נכנסות לאישור.
- **הניקוד שלי** – לכל מחזור, מול הממוצע של מי שנמדדים איתו, עם קישור ל"איך מחושב הניקוד".
- **למי לפנות** בתחתית – אנשי הקשר שאחראי השיבוצים בחר, עם וואטסאפ וחיוג.
- הפעלת התראות לטלפון.

![המשימות שלי – החלפה שמחכה לאישור, "ראיתי את כולן", והמשימה הבאה עם תדריך, איש קשר והערה](/spec/13-my-duties.webp)

### הבקשות שלי

- רשימה אחת של כל הבקשות – פטור, חסימה, היעדרות – הקרובות קודם, עם תאריכים, סטטוס וביטול. מה שעבר זמנו תחת "קודמות".
- כפתור אחד **בקשה חדשה** ששואל "מה קרה?" ומוביל לטופס המתאים. מכסת החסימות מוצגת בטופס, לחודש שנבחר.
- מועד שנסגר: משפט אחד מה אפשר לעשות עכשיו (פטור דחוף), וכפתור "למי לפנות".
- הטפסים מזכירים לא לכתוב מידע רפואי.

![הבקשות שלי – מועד שנסגר, פטור שממתין, ולמי לפנות](/spec/14-my-requests.webp)

### אנשי קשר לעובדים

בהגדרות › אנשי קשר לעובדים אחראי השיבוצים בוחר מי מוצג ב"למי לפנות", באיזה שם ובאיזה סדר. כל עובד רואה עד שניים מאחראי השיבוצים ומ"מ, ואת מפקד המסגרת שלו אם הוא ברשימה. הרשימה מוצגת בשורות; הוספה ועריכה בחלון קטן, וכל שינוי נשמר מיד. הטלפון נכתב שם, או נלקח מכרטיס העובד. הטלפונים של מי שלא ברשימה לא מוצגים. כל עוד לא נבחר איש קשר, תמונת המצב מזכירה.

### צפייה בלי קליטה

האפליקציה נפתחת גם בלי חיבור, ו"המשימות שלי" מציגות את העותק האחרון עם "אין חיבור – מוצג מצב מ-…". העותק נשמר במכשיר לכל משתמש בנפרד, רק המשימות שלו, נמחק ביציאה, לא מוצג אחרי 14 יום, ונמחק גם לעובד שהשירות שלו הסתיים. בלי חיבור – פעולות מושבתות. כשיש חיבור הדף נטען תמיד מהשרת, וקובץ של האפליקציה שחסר בשרת (עדכון גרסה באמצע) מעביר למסך העדכון של הינשוף – כך המכשיר לא נתקע על גרסה ישנה.

### סיור היכרות

בכניסה הראשונה – שלושה צעדים קצרים עם הינשוף, לפי התפקיד, כולל איך מוסיפים את האתר למסך הבית (אייפון ואנדרואיד) ומפעילים התראות. אפשר לפתוח שוב מהתפריט.

## 11. מסכי הסגל והמפקדים

### תמונת מצב (אחראי השיבוצים ומ"מ)

דף הבית של הסגל – מה מחכה היום:

- **לא אישרו – 72 השעות הקרובות** (פרק 9).
- **הצעות ומשוב** – רק מה שעוד מחכה: חדשות ובטיפול, עם הטיפול בכל אחת ו"לכל ההצעות". כשאין מה שמחכה – לא מוצג.
- **המחזור בעבודה** – השלב והצעד הבא.
- **השבוע הקרוב** – כמה משימות מפורסמות וכמה לא מאוישות.
- תזכורות: בקשות לתאריכים בלי מחזור, איש קשר לעובדים שלא נבחר, אחד בלבד שיכול לאפס אימות, החלפות אחרונות, והמשימה הבאה שלך.

### נתוני היחידה

דף הבית של מפקד היחידה, ופתוח גם לאחראי השיבוצים ולמפקדי המסגרות: בקשות פטור ממתינות, הגישו בעצמם, עובדים עם חשבון אישי, שינויי הגדרות של אחראי השיבוצים (מיומן הביקורת – 10 האחרונים, עם "הצג את כולם"; שינוי זהה ברצף מוצג פעם אחת עם ×N), העומס לפי מסגרת ולפי אוכלוסייה, הסופ"ש הקרוב, והצעות ומשוב.

![נתוני היחידה – המונים, העומס לפי מסגרת ולפי אוכלוסייה, הסופ"ש הקרוב ושינויי ההגדרות](/spec/11-dashboard.webp)

### הצעות ומשוב

- **הצעה לשיפור:** כל משתמש שולח רעיון, תקלה או הערה – מהתפריט, מאייקון הנורה או מסוף הסיור. אפשר בלי שם: אז שום דבר לא מקשר את ההודעה אליו, גם לא מזהה המשתמש. עד 5 ביום. נשמרים המסך, הגרסה וסוג המכשיר.
- **הטיפול** (אחראי השיבוצים, מ"מ, מפקד יחידה): סטטוס – חדש, בטיפול, בוצע, לא ייעשה – ותשובה לשולח. מי ששלח בשמו מקבל עדכון בפעמון כשמסמנים "בוצע" או "לא ייעשה". 10 בכל פעם, עם "עוד".
- **במסך הראשי** (תמונת המצב, נתוני היחידה) מוצגות רק חדשות ובטיפול, בלי סינון. מה שסומן "בוצע" או "לא ייעשה" יורד מיד, לכל הסגל. הרשימה המלאה עם הסינון – ב"לכל ההצעות".

### מסמך האפיון

המסמך הזה, בתפריט, לסגל ולמפקדים (מסגרות ויחידה), עם צילומי המסך, תוכן עניינים והדפסה. הטקסט נשמר במסד עם בדיקת תפקיד ולא בקוד הציבורי; עובדים וההדגמה לא רואים אותו.

## 12. לוח השיבוצים

הלוח המפורסם, פתוח לכולם, בלי פרטים רגישים – בלי פטורים, ניקוד והסברים.

- **תצוגות:** רשימה לפי ימים (ברירת מחדל), חודש (בכל יום המשימות עם מספר; בטלפון נקודות צבע) ושבוע (משימה × יום; בטלפון שורת ימים שלחיצה עליה פותחת את היום).
- **טווחים:** השבוע, הבא, הסופ"ש הקרוב, חודש – גם מחזור עתידי שכבר פורסם.
- **שורה לכל משימה:** שם ושעות ("יממה · 08:00", "20:00–08:00 למחרת"), המבצע עם המסגרת, העתודה, ו-ⓘ להנחיות, התייצבות ותדריך. לא מאוישת – באדום. עתודה שהופעלה – "עתודה שהופעלה: X · במקום Y". ⚡ ליד מי שהוקפץ. "עודכן" ליד מה שהשתנה אחרי הפרסום.
- **חיפוש וסינון:** לפי שם (מדגיש), מסגרת וסוג.
- **ליומן:** קובץ ics עם המשימות הקרובות של עובד ותזכורת. השם נלקח מהחיפוש, או נכתב בחלון.
- **בטלפון:** בחירת התצוגה, הטווח והתאריכים – כל אחד בשורה מלאה, בחלקים שווים.
- **הדפסה:** חודש בדף A4 לרוחב, ימים בשורות ומשימות בעמודות, קו עבה בין שבועות, סוף שבוע וחג מוצללים. ההדפסה תמיד בהירה.
- **לאחראי השיבוצים:** לחיצה על משימה פותחת את פעולות התפעול.

## 13. התראות

ההתראות מגיעות לפעמון באפליקציה (עם מונה), ולטלפון כהתראת דחיפה (Web Push) למי שהפעיל. באייפון – אחרי "הוספה למסך הבית". אין SMS ומייל. השעון של התזכורות הוא המסד עצמו (pg_cron, כל 15 דקות).

## 15. מראה ומיתוג

- **השם תורנצ׳יק** והינשוף במדי עבודה כחולים עם פסים כתומים – ער בלילה, שומר ומסדר. הצבעים שלו (כחול #1a1466, כתום #e8700f) הם צבעי הממשק.
- **התנוחות:** מנופף (כניסה), מחזיק לוח (מסכים ריקים), מצביע (מה חדש, הסבר), חוגג (פרסום), מבולבל (שגיאה, אין חיבור, עדכון גרסה), ישן (אין משימות). ראש הינשוף הוא אייקון האפליקציה וההתראות, וראש מתנדנד מסמן שהמנוע רץ.
- **איפה לא:** במסכי ניהול צפופים, בהודעות רגישות (דחייה, מחיקה, ביטול פרסום) ובתוך הלוח.
- **בלי סימנים צבאיים:** אין סמל יחידה ואין שם יחידה – לא בכניסה, לא בהדפסה ולא בשם האפליקציה. הדרגות בשמות חלופיים (פרק 4).
- **יום ולילה:** כפתור אחד בסרגל ובמסך הכניסה – ירח עובר למצב לילה, שמש למצב יום. עד הלחיצה הראשונה – לפי הגדרת המכשיר. הבחירה נשמרת במכשיר ובחשבון. ההדפסה תמיד בהירה.
- **עדכון גרסה:** כשיוצאת גרסה בזמן שהאפליקציה פתוחה, הינשוף מודיע שהמערכת מתעדכנת וטוען לבד. "מה חדש" נפתח ממספר הגרסה בתפריט.
- **שפה:** עברית מלאה מימין לשמאל, משפטים קצרים, בלי קודים טכניים בהודעות שגיאה.

## 16. אבטחה ופרטיות

- **מה לא נשמר:** מסמכים רפואיים, אבחנות, סיבת פטור בטקסט חופשי, מספר אישי, מספר זהות ומספר עובד.
- **מזהה עובד:** מספר העובד משמש רק בדפדפן של אחראי השיבוצים בזמן טעינה או הוספה, ומומר למזהה מוצפן (HMAC-SHA256) עם מפתח היחידה, שלא נשמר בשרת. רק המזהה עולה.
- **הרשאות בשרת:** כל טבלה מוגנת ב-Row Level Security; טבלה בלי מדיניות חסומה. פעולות רגישות עוברות בפונקציות שבודקות תפקיד. מפקד מסגרת רואה פרטים אישיים רק של המסגרת שלו. עובד שהשירות שלו הסתיים לא מקבל נתונים, גם בחיבור פתוח.
- **הלוח המשותף** הוא view שמחזיר רק את המותר לכולם.
- **הזדהות:** Supabase Auth; שם המשתמש נשמר מול כתובת פנימית שלא מקבלת מייל. אימות דו-שלבי (TOTP) חובה לסגל ולמפקדים.
- **יומן ביקורת:** כל שינוי בנתונים ובהגדרות נרשם, ואי אפשר למחוק או לשנות אותו מהאפליקציה – גם לא אחראי השיבוצים. רק סקריפט הניקוי (פרק 17) מאפס אותו. טיוטות של המנוע לא נרשמות שורה-שורה. טלפון נרשם בלי המספר.
- **מנוע השיבוץ** רץ בתפקיד מסד נתונים מוגבל, שעושה רק את עבודת המנוע.
- **אנשי קשר:** רק הטלפונים שאחראי השיבוצים בחר מוצגים לעובדים.
- **מיקום:** Supabase באירופה. HTTPS בכל הערוצים. גיבוי יומי מוצפן.
- **אישור אבטחת מידע** להחזקת שמות, מסגרות ושיבוצים בענן אזרחי – נדרש לפני עלייה לאוויר מלאה.

## 17. ארכיטקטורה ותפעול טכני

| רכיב | בפועל |
| --- | --- |
| ממשק | React + TypeScript (Vite) ו-MUI עם RTL, PWA עם service worker. אירוח: Cloudflare Workers (קבצים סטטיים, כתובת workers.dev) |
| מסד ולוגיקה | Supabase PostgreSQL. כל הלוגיקה בפונקציות SQL ו-RLS, בלי שרת API |
| הזדהות | Supabase Auth, סיסמה ו-TOTP |
| מנוע | Python + OR-Tools CP-SAT ב-GitHub Actions (workflow "solve"), מופעל מהמסד דרך pg_net עם טוקן ב-Supabase Vault |
| התראות | pg_cron כל 15 דקות מוסיף תזכורות; workflow "notify" שולח Web Push (VAPID) |
| גיבוי | workflow "backup" – כל לילה ולפני כל מיגרציה: pg_dump מוצפן בסיסמה (BACKUP_PASSPHRASE), נשמר 30 יום. שחזור – ב-README |
| מיגרציות | קבצי SQL ממוספרים, מופעלים אוטומטית בכל מיזוג ל-main (workflow "db-migrate") |
| בדיקות | בכל שינוי: ממשק (~210 בדיקות vitest), מסד נתונים כולל הרשאות (~110 בדיקות pytest), מנוע; ובדיקה שאין DELETE/UPDATE בלי WHERE בפונקציות |
| שמירה בחיים | keep-alive כל 3 ימים, כדי שהפרויקט החינמי לא יושהה |
| הדגמה | אותה אפליקציה עם נתונים פיקטיביים בדפדפן, בלי שרת |

- **ניקוי נתוני בדיקה:** הסקריפט supabase/reset_dynamic_data.sql (מורץ ב-SQL Editor) מוחק את כל הנתונים – מחזורים, עובדים, מסגרות, חשבונות עובדים, בקשות, התראות, משוב ויומן הביקורת – ומשאיר את כל ההגדרות ואת חשבונות הסגל. לפני המחיקה הכל מועתק לסכמת reset_backup.
- **גרסאות:** לכל שינוי מספר גרסה ויומן "מה חדש" שמוצג למשתמשים.
- **מגבלות השכבה החינמית:** 500MB מסד, השהיית פרויקט אחרי שבוע בלי פעילות (נמנע ב-keep-alive), אין SLA. מעבר ל-Supabase Pro לא דורש שינוי קוד.

## 19. מה עוד לא נבנה ושאלות פתוחות

**לא נבנה:**

- קנסות מהבסיס ומשבצות קנס, וערעורים במערכת.
- ייבוא היסטוריה מקובץ (ההיסטוריה נבנית מהמחזורים שמנוהלים במערכת).
- סימון "הופל" ו"בוצע" אחרי משימה, ותדריך – מי הגיע.
- דוחות לייצוא (עומס, השוואת מסגרות, הוגנות לאורך זמן).
- חילופי מפקדים מתוזמנים עם תקופת חפיפה.
- גרירת עובד בין משבצות בטיוטה.

**פתוח לבירור:**

- ועדת המרות – מה הכלל?
- אילו סוגי היעדרות "לא מבחירה" מעבר לקורס ומחלה.
- אישור אבטחת מידע לעלייה לאוויר מלאה, וחשבונות השירותים על כתובת של היחידה עם שני מנהלים.
